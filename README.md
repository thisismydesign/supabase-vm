# supabase-vm

Self-hosted Supabase, one VM per project, on a VPS. The VM is the boundary: whatever happens on the host (tool installs, Docker restarts, agents) does not reach it.

- **VM** — incus on the host, Ubuntu image, fixed CPU, memory and disk, autostart.
- **Supabase** — the official self-hosting bundle inside the VM, keys generated by its own scripts, Docker publishing on localhost only.
- **Access** — a proxy inside the VM forwards to the API on localhost. No port is opened on the host. Two options:

| Access     | Tailscale (no domain needed)                                           | Cloudflare (own domain)                                                              |
| ---------- | ---------------------------------------------------------------------- | ------------------------------------------------------------------------------------ |
| Public API | Funnel at `https://<vm>.<tailnet>.ts.net`                              | Tunnel at `https://<vm>.<domain>`                                                    |
| Studio     | Same URL, dashboard password                                           | Same URL, dashboard password                                                         |
| Deploy     | Tailscale GitHub Action joins CI to the tailnet; Postgres 5432, SSH 22 | SSH at `<vm>-ssh.<domain>` behind Cloudflare Access; Postgres is forwarded over it   |
| Shell      | `ssh -i ~/.ssh/<vm>-ci ubuntu@<vm>` over Tailscale                     | `incus exec <vm> -- bash` on the host                                                |
| Depends on | Tailscale relays and account; disable key expiry per device            | Cloudflare, the domain's zone, a Zero Trust team; 100 MB per upload on the free plan |

Hostnames sit one label under the domain: Cloudflare's free certificate covers `*.<domain>` and nothing deeper.

## Host, once

```sh
git clone https://github.com/thisismydesign/supabase-vm
```

`host/create-vm.sh` installs incus and the firewall rules on first use.

The host MUST have no public ports, and its ufw MUST drop new connections from the public interface in `DOCKER-USER`. `/etc/ufw/after.rules` MUST declare `DOCKER-USER` once; `create-vm.sh` declares it only when no earlier block does. Check with `sudo iptables -L DOCKER-USER -n`.

## Per project

Tailscale:

```sh
host/create-vm.sh supabase-<project> https://<frontend-url>   # creates the VM and starts the stack, latest Supabase release
# approve the printed Tailscale login URL, then:
incus exec supabase-<project> -- /opt/supabase-vm/expose.sh      # Funnel for the API, tailnet TCP for Postgres
```

Cloudflare:

```sh
SUPABASE_DOMAIN=<domain> host/create-vm.sh supabase-<project> https://<frontend-url>
incus exec supabase-<project> -- /opt/supabase-vm/expose.sh <team> <aud>   # prints a login URL; approve it for the domain's zone
```

`<team>` and `<aud>` let CI deploy. In Zero Trust, create a service token and a self-hosted Access application for `supabase-<project>-ssh.<domain>` whose only policy is Service Auth for that token; `<team>` is the team name, `<aud>` the application's audience tag. Without them `expose.sh` serves the API only; run it again with them later.

The zone SHOULD bypass cache for the API hostname: Cloudflare caches image extensions by default, and a cached copy outlives a signed Storage URL.

`SUPABASE_REF=self-hosted/v0.8.3 host/create-vm.sh ...` pins a [release](https://github.com/supabase/supabase/tags); the VM records its version in `/opt/supabase/.supabase-version`.

`SUPABASE_EXCLUDE=realtime,imgproxy host/create-vm.sh ...` leaves services of the bundle off; the default runs all of them. Names are the bundle's Compose services. `services.sh` changes the set on a running VM (see Operate); an excluded service keeps its data.

| Service     | Without it                                                |
| ----------- | --------------------------------------------------------- |
| `studio`    | No dashboard at the public URL; `meta` serves only Studio |
| `realtime`  | No Realtime                                               |
| `storage`   | No Storage; `imgproxy` serves only Storage                |
| `imgproxy`  | Storage without image transformations                     |
| `functions` | No Edge Functions                                         |

`supavisor` MUST stay: deploys reach Postgres through it.

Keys and passwords live in `/opt/supabase/.env` inside the VM. Keep a copy as `.env.supabase-<project>` in this checkout; it is gitignored.

## Deploying a project to it

From GitHub Actions, in the project's deploy job. `create-vm.sh` generates the SSH key on the host as `~/.ssh/<vm>-ci` and authorises it for `ubuntu` in the VM; its private half is a repo secret. The frontend gets the public URL as `SUPABASE_URL`, and `SUPABASE_PUBLISHABLE_KEY` from `.env`.

Tailscale, after joining the tailnet with `tailscale/github-action` (OAuth client tagged `tag:ci`):

```sh
supabase db push --db-url "$SUPABASE_DB_URL"        # postgresql://postgres.<tenant>:<password>@<vm>.<tailnet>.ts.net:5432/postgres?sslmode=disable
tar -cf - -C supabase/functions . | ssh ubuntu@<vm>.<tailnet>.ts.net 'cd /opt/supabase/volumes/functions && find . -mindepth 1 -maxdepth 1 ! -name main -exec rm -rf {} + && tar -xf -'
ssh ubuntu@<vm>.<tailnet>.ts.net 'cd /opt/supabase && docker compose restart functions'
```

The tailnet policy MUST let `tag:ci` reach the VM on 22 and 5432; Tailscale SSH is off in the VM, so OpenSSH and `authorized_keys` decide, not the SSH policy.

Cloudflare, with [cloudflared](https://github.com/cloudflare/cloudflared) on the runner and the service token in `TUNNEL_SERVICE_TOKEN_ID` and `TUNNEL_SERVICE_TOKEN_SECRET`:

```sh
printf 'Host <vm>-ssh.<domain>\n  User ubuntu\n  ProxyCommand cloudflared access ssh --hostname %%h\n' >> ~/.ssh/config
ssh -fN -L 5432:localhost:5432 <vm>-ssh.<domain>
supabase db push --db-url "$SUPABASE_DB_URL"        # postgresql://postgres.<tenant>:<password>@localhost:5432/postgres?sslmode=disable
tar -cf - -C supabase/functions . | ssh <vm>-ssh.<domain> 'cd /opt/supabase/volumes/functions && find . -mindepth 1 -maxdepth 1 ! -name main -exec rm -rf {} + && tar -xf -'
ssh <vm>-ssh.<domain> 'cd /opt/supabase && docker compose restart functions'
```

`sslmode=disable` because the pooler speaks no TLS; the tailnet or the tunnel encrypts. `tar` over `ssh` because the image has no rsync.

Manual fallback from the host: `host/deploy-functions.sh <vm> supabase/functions`, and `db push` against the same URL.

## Footprint

Defaults: 4 vCPU, 4 GiB, 30 GiB, settable per VM on `create-vm.sh`. Measured on an idle VM running every service, 2026-10-31:

| Resource | Use                                                                                  |
| -------- | ------------------------------------------------------------------------------------ |
| CPU      | Load ≈ 0.5 of 4 cores                                                                |
| Memory   | ≈ 1 GiB for the containers, ≈ 1.7 GiB for all guest processes; the host sees the full limit once the guest's page cache fills it, and it does not shrink |
| Disk     | 13 GiB on the host after install, 10 GB of it Docker images. The disk is sparse, so the limit is a cap, not a cost; it must fit two image sets during an upgrade. It cannot be shrunk later |

Memory is a hard cap: the guest drops cache, then kills a container, and the host is never affected. Change it live with `incus config set <vm> limits.memory=4GiB`.

## Operate

| Task       | Command                                                                      |
| ---------- | ---------------------------------------------------------------------------- |
| Shell      | `incus exec supabase-<project> -- bash` on the host                          |
| Studio     | The public URL, dashboard user and password from `.env`                      |
| Snapshot   | `incus snapshot create supabase-<project> before-<change>`                   |
| Roll back  | `incus snapshot restore supabase-<project> before-<change>`                  |
| Upgrade    | `incus exec supabase-<project> -- bash -c 'cd /opt/supabase && sh update.sh && docker image prune -af'`; add `--to self-hosted/vX.Y.Z` for a specific release |
| Services   | `incus exec supabase-<project> -- /opt/supabase-vm/services.sh realtime,imgproxy` excludes those; no argument runs them all |
| Logs       | `incus exec supabase-<project> -- docker compose -f /opt/supabase/docker-compose.yml logs -f` |
